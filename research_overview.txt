1. ABSTRACT
================================================================================

Raga Vision is an AI-powered system that automatically identifies Indian Classical
Music Ragas from audio recordings and provides music therapy recommendations. It
combines Deep Learning (Neural AI) with Musicological Rule-Based Logic (Symbolic AI)
in a novel Neuro-Symbolic architecture — making it one of the first hybrid systems
specifically designed for the domain of Hindustani Classical Music.

The system accepts raw audio files (WAV, MP3, Opus, etc.), performs multi-stage
acoustic analysis, classifies the Raga, and maps the result to therapeutic wellness
recommendations based on the emotional qualities of the identified Raaga.


================================================================================
2. PROBLEM STATEMENT
================================================================================

Indian Classical Music (ICM) Ragas are complex melodic frameworks that form the
backbone of Hindustani music. Unlike Western scales, Ragas have:
  - A fixed set of Swaras (notes) including specific Komal (flat) and Tivra (sharp) variants
  - Characteristic Pakads (signature melodic phrases)
  - Arohana-Avarohana (ascending-descending) movement rules
  - Time-of-day associations (morning, evening, night)
  - Vadi (dominant) and Samvadi (sub-dominant) notes that define musical grammar

Automated Raga recognition is extremely difficult because:
  1. The same note may appear in multiple Ragas
  2. Ragas can be identified only through a combination of melodic grammar + note usage
  3. Traditional deep learning models lack musicological awareness
  4. Audio quality, performance style, and tempo variations create noise

This project addresses these challenges through a multi-layered hybrid approach.

3. SYSTEM ARCHITECTURE — OVERVIEW
================================================================================

The system follows a 6-Phase Hybrid Inference Pipeline:

  [Audio Input]
      |
      v
  PHASE 0: Tonic Locking (Sa Estimation)
      |
      v
  PHASE 1: Audio Chunking (20s windows, 10s step)
      |
      v
  PHASE 2: Feature Extraction (per chunk)
      |   - Swara Detection
      |   - Arohana-Avarohana
      |   - Pakad / Signature Phrases
      |   - Gamakas (ornaments)
      |   - Vadi/Samvadi
      |   - Transitions + Timbre
      v
  PHASE 3: Aggregation (cross-chunk)
      |
      v
  PHASE 4: Hybrid Classification (Symbolic + Cosine + Pakad)
      |
      v
  PHASE 5: Neural Mood Detection (CLAP — Contrastive Language-Audio Pretraining)
      |
      v
  PHASE 6: Visualization + Therapy Recommendation
      |
      v
  [JSON Response → React Frontend]

5. FEATURE EXTRACTION PIPELINE — DETAILED
================================================================================

A. TONIC ESTIMATION (Sa Locking)
   The tonic frequency (Sa / root note) is the reference point for all Swara
   calculations. The system uses a two-step approach:
   Step 1: Acoustic Estimate — histogram peak of MIDI pitch classes in mod-12 space
   Step 2: Symbolic Refinement — all 12 candidate tonics are tested; the one that
           maximizes "Raga Conformity Score" (how well the audio fits any known Raga
           grammar) is selected as the locked tonic.

B. SWARA DETECTION
   - Raw F0 is converted to semitone intervals relative to locked tonic
   - Quantized to nearest 12-note pitch class
   - Collapsed into a sequence of distinct consecutive notes
   - Each Swara duration, frequency, and appearance count is computed

C. AROHANA-AVAROHANA DETECTION
   - F0 sequences are split into ascending (Arohana) and descending (Avarohana) runs
   - The longest ascent/descent sequences are selected as the Raga's scale structure

D. PAKAD DETECTION
   - N-grams (4-note sequences) are counted across the full recording
   - Most frequent 4-note phrases are identified as candidate Pakads
   - These are cross-referenced against the Raga knowledge base for grammar scoring

E. GAMAKA ANALYSIS
   - Oscillations: Count of pitch direction changes (meend, gamak detection)
   - Slides: Detected if pitch variation exceeds 15 Hz between adjacent frames
   - Average pitch variation: Mean absolute pitch derivative (Andolan index)

F. VADI-SAMVADI ESTIMATION
   - The most frequently occurring note becomes the empirical Vadi
   - The second most frequent is the empirical Samvadi
   - These are compared to the knowledge base's expected Vadi/Samvadi per Raga

G. TIMBRE FEATURES
   - MFCC (13 coefficients): Captures vocal/instrument texture
   - Spectral Centroid: High = bright, Low = warm/deep timbre
   - Zero Crossing Rate: Estimate of noisiness / percussiveness

H. ADVANCED ANALYTICS
   - Sa Stability Score: Proportion of notes that are exactly Sa (tonic) —
     indicates how grounded the performance is
   - Nyas Swaras: Notes that appear most often at phrase endings —
     indicates resting/anchor notes of the performance

6. CLASSIFICATION ENGINE
================================================================================

The classifier combines three scoring mechanisms:

A. COSINE SIMILARITY (40% weight)
   Input swara distribution vector (12D) vs. template vector from raga_templates.json
   Measures note usage similarity across all Ragas simultaneously.

B. TRANSITION SCORE (20% weight)
   Bigram (note-pair) statistics from the audio are compared to expected transition
   probability distributions in the Raga template. Uses square-root normalization
   to handle sparse transition data.

C. PAKAD SCORE (30% weight)
   Longest Common Subsequence matching between detected 4-note phrases and each
   Raga's canonical Pakads. Match threshold: >70% → 0.4 score, >50% → 0.2 score.

D. RANGE SCORE (10% weight)
   Normalized pitch range. Wider range → higher coverage of the Raga's octave.

E. VADI SCORE (5% weight, bonus)
   +1 if the empirical dominant note matches the Raga's defined Vadi note.

Final scores are passed through a Softmax function with temperature T=0.3 to
produce confidence probabilities that emphasize the winner and suppress near ties.

F. FORBIDDEN NOTE PENALTY (applied in symbolic layer)
   If a note that is forbidden in a Raga appears with >3% frequency, a severe
   penalty of 15x its weight is subtracted — implementing musicological exclusion logic.

7. NEURAL MOOD CLASSIFICATION (CLAP)
================================================================================

The CLAP (Contrastive Language-Audio Pretraining) model from LAION is used to
determine whether the Raga is a "Day" or "Night" Raga.

Four text descriptions encode temporal mood:
  1. "Prabhat Samay early morning Hindustani classical raga with komal swaras..."
  2. "Madhyahna bright midday Indian classical raga with sharp melodic movements..."
  3. "Sayankal romantic evening Hindustani raga with deep resonance..."
  4. "Ratri deep meditative late night Indian classical raga..."

The model:
  - Encodes these texts into latent semantic vectors at startup (cached)
  - At inference, encodes the first 5 seconds of audio
  - Computes cosine similarity between audio and all 4 text embeddings
  - Applies Softmax → Day probability = P(morning) + P(midday)
  - Night probability = P(evening) + P(night)

This provides a cross-modal (audio-text) neural verification of the symbolic
time-of-day classification.


================================================================================
8. MUSIC THERAPY ENGINE
================================================================================

Purpose: Map the acoustic properties of the identified Raga to physiological and
         psychological therapeutic applications. Based on principles of Raga Chikitsa
         (Raga Therapy) — an ancient Indian practice now supported by modern research.

Therapy Scores Computed:
  - Calm Score (0-10): Inversely correlated with tempo and pitch volatility.
                       High score → suitable for meditation, sleep, stress relief.
  - Energy Score (0-10): Correlated with high tempo, Gamaka intensity, transitions.
                         High score → suitable for exercise, motivation, vitality.
  - Focus Score (0-10): Correlated with moderate tempo, clean transitions, stable pitch.
                        High score → suitable for study, concentration, productivity.

Recommendation Categories:
  - Dominant Calm → "Stress Relief, Meditation, and Deep Sleep"
  - Dominant Energy → "Motivation, Physical Workout, and Vitality"
  - Dominant Focus → "Study, Cognitive Concentration, and Productivity"

The system generates natural-language explanations linking each musical feature
(tempo, pitch range, Gamakas, transitions) to its physiological rationale.


================================================================================
9. VISUALIZATION ENGINE
================================================================================

Three types of visualizations are automatically generated:

  1. Acoustic Spectrogram (Mel-based, rendered in browser)
     - 128 Mel frequency bands
     - Color-mapped (black → red → yellow → white) based on energy
     - Rendered on HTML5 Canvas for zero-latency display

  2. Pitch Contour Plot (PNG, generated by matplotlib)
     - F0 trajectory over time
     - Highlights voiced vs. unvoiced regions

  3. Full Analysis Dashboard (PNG, pre-generated or dynamic)
     - Combines pitch contour, spectrogram, note histogram, and Raga scores
     - Saved to /output/ or /static/ directory and served via FastAPI static mount


================================================================================
10. BULK PROCESSING CAPABILITY
================================================================================

The /classify_bulk endpoint accepts 2-50+ audio files simultaneously.
For each file:
  - Independent tonic locking
  - Full feature extraction pipeline
  - Raga classification
  - Therapy profiling
  - Spectrogram generation

Results are aggregated and returned as a structured JSON array, displayed in a
sortable table with expandable rows showing Explanation, Visual Analytics, and
Therapy Analysis panels per file.

15. LIMITATIONS & FUTURE WORK
================================================================================

Current Limitations:
  - Knowledge base covers only 8 Ragas (extensible via raga_templates.json)
  - Tonic estimation may fail on heavily accompanied/orchestral recordings
  - CLAP model is a general-purpose audio model, not ICM-specific
  - Polyphonic (multiple simultaneous instruments) audio is not supported

Future Enhancements:
  - Expand Raga knowledge base to 50+ Ragas
  - Train a fine-tuned ICM-specific CLAP/audio encoder on Raga datasets
  - Add Gharana (school of music) detection
  - Implement real-time streaming classification
  - Integrate Raga Raag-mala (sequence of Ragas) detection for full concerts
  - Build a mobile-compatible progressive web app (PWA)
  - Develop a REST API for third-party integration with music platforms
